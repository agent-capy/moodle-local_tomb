# 0.2アルファ版の継続実装

2026-09-20：ユーザーの継続指示を受領。0.1.0-alphaは初回PoCの到達点であり、48時間計画全体の完了とは扱わない。Gitの作者・コミッターを指定アカウントへ修正し、モデル名を含むCo-authorを記録する。

今回の優先事項：

1. Privacy APIの利用者検索・データ出力・承認済み削除。教師版・フォーラム内の他者データも追跡する。
2. 教師版の評価・講評を、教師自身の閲覧権限の範囲まで拡張する。学生版の秘匿を維持し、対になる試験を行う。
3. 完成後の権限失効、通知先の停止、収集完了後のZIP準備失敗、本番移行時の検証データを扱う。
4. Moodle統合試験・ブラウザ再確認・既存版の不変性確認、文書・配布物・実画面の更新。

既存の0.1.0-alpha記録には、他者の寄与内容を特定する索引がない。旧版のZIPを変更せずに保持し、移行制限を明示する。新しい索引を持たない版が残っている間は本番モードへの移行を許可しない。元データを読み直して過去の版を書き換えることはしない。

## 今回の到達点

上記4項目を0.2.0-alphaとして実装・共有Moodleへ反映した。検索・標準writer出力・承認済み削除と寄与内容の索引、教師の非公開評価、権限失効、通知先停止、ZIP準備だけの失敗、運用モードの競合を扱った。一括受付は利用者ごとに成功・失敗を返す。

Privacy削除は、本人の記録を消去し、他者版に本人の寄与が含まれる場合はその版全体の保存材料を廃棄して配信を停止する。元のMoodle資料は消さない。使用中の全対象をロックできない場合は削除を始めない。監査は削除対象を伏せた新しい連鎖と旧連鎖の最終ハッシュを記録する。小テストの手動講評は採点者へ対応付け、教師の個人データ応答に学生の解答を混ぜない。

[0.2検証結果](VALIDATION_0_2.md)と[追加画面](SCREENSHOTS.md)を保存した。新しい学生版36・教師版35は通常画面と通常cronから生成・取得。旧版2・11の再構成結果も以前のSHA-256と一致した。Moodle本体・他プラグイン・共有サイトのサービス設定は変更していない。
