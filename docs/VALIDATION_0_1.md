## 試験中の不具合と修正

- 初回導入で予約語の列名とMoodle5.0の通知定数に不備を検出し、Tombだけを修正した。言語/バージョンキャッシュと導入完了情報も更新し、通常cronの保留を解消した。全体アップグレードは実行していない。
- 組み合わせ問題の選択値がHTML除去処理で失われる不備、root実行cronのZIPにWebユーザーがmtime設定する不備を修正し、実出力で再確認した。
- 内容の陽性確認で、Moodleが除去するHTMLコメントを目印にした試験を修正した。実際の表示本文で可視性を再確認した。
- MySQLロックは同一DB接続内で再取得できる。容量保護試験を別PHPプロセス・別DB接続へ修正して再確認した。初回の試験で清掃されたTombキャッシュは、保持材料から元と同じハッシュへ再構成した。
- 提供された既存管理者の認証情報は最終確認時にログインが拒否された。既存パスワードは変更していない。専用教師へTomb管理・監査の2権限だけを一時付与して管理画面を検証し、試験後にロールを削除した。サイト管理者ログイン自体の成功とは扱わない。

## 再実行と未検証事項

純粋処理はローカル、Moodle統合は専用fixtureと検証モードでのみ実行する。キャッシュ試験は破損させてよい専用学生版を指定し、`--request=ID --corrupt`、本人によるダウンロード要求、`--request=ID --run` の順で実行する。他の学習記録や共有ディスクを満杯にする方法で再現しない。プロセス内の強制設定は終了時に復元し、通常運用の設定値は変更しない。

Windows/Safariの実機、他のMoodle版、数千人の大量配送、帯域制御下の長時間ダウンロード、全小テスト形式、全活動、H5P/SCORM/LTI、詳細ルーブリック、停止済みアカウントへの交付、Privacy API自動エクスポート/消去は未検証または未実装。キャッシュの並行保護は独立接続で確認したが、実運用負荷の性能試験ではない。
