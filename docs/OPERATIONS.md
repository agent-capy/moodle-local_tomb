# 運用・開発手順

## 導入

設置先は Moodle の `local/tomb`。専用インストーラはTombの導入・更新だけを行う。

導入前に他プラグインのソースと DB 版を確認する。専用 `cli/install.php` は全プラグインの一致を確認し、`local` 型の更新処理でも Tomb 以外への更新コールバックを拒否する。CLI プロセス内でクラス・言語キャッシュを更新し、導入完了のバージョン情報を記録する。サイト全体のアップグレード CLI は実行しない。

新規配置は、完全なディレクトリを用意してから行い、導入完了まで連続して実施する。Moodle が新プラグインを検出してから導入が完了するまでは、通常 cron が保留される場合がある。完了後は `moodle_needs_upgrading()` が false であること、通常ログイン・コース表示・通常 cron の完了を確認する。

既存 Tomb の更新前には、そのディレクトリと Tomb の設定・テーブルを必要に応じて保全する。復旧時にサイト全体の DB リストアや初期化を行わない。

0.3（DB版 `2026092002`）では要求テーブルに `outputlang`・`metrics` と要求者索引を追加する。更新前後の実行コードを混在させないよう、Tombだけを停止し、Tombの処理ロックを確保して専用インストーラを実行し、元のモードへ戻す。サイトのメンテナンスモードは使わない。

0.3.1（版 `2026092800`）は教師用のコース選択・出力判定を修正する。テーブル構造の変更はない。更新時は同じ専用インストーラを実行して、版情報と言語キャッシュを更新する。

## 設定

| 項目 | 既定・扱い |
|---|---|
| 運用モード | `disabled`。管理画面で変更・監査 |
| 検証 | `rehearsal`。指定コーホートに限定、配送期限の設定は不要 |
| 本番 | `active`。配送期限と環境確認が必要 |
| 配信のみ | `delivery_only`。新しい収集要求を受け付けない |
| 配送期限 | Unix timestamp。期限後は取得停止し、材料は削除操作まで保持 |
| ZIP キャッシュ | 合計2 GiB、TTL最長21600秒。使用中のキャッシュは削除しない |
| 空き容量 | 5 GiBとボリュームの10%の大きい方。生成時はデータ・一時領域も確認 |
| ZIP置場 | 既定 `moodledata/local_tomb_cache`。Webルート外を必須とする |
| 生成・組立 | 全体で1件のワーカーロック |
| 配信数 | 既定1、設定は1〜8に制限 |
| 新版の間隔 | 既定300秒。同じ版のキャッシュ再構成は別扱い |

期限は配送用 ZIP キャッシュの期限とは別である。キャッシュが消えても、材料が残り利用資格があれば同じ版を再準備できる。期限後の材料削除は管理画面で版を選び、再取得不能になることを確認して実施する。元の Moodle 資料・他プラグインのファイルは削除しない。組立計画・注記・監査は残す。

本番への切り替え前に、検証版の材料を管理画面で明示的に削除し、監査記録を保持する。モードを変えるだけで検証版を本番として配信することはできない。0.2では、検証版または索引のない旧版の材料が残る場合に本番への切替を拒否する。自動一括削除は行わない。

## 教師版の出力条件

「教師版・学生の作成代行」からコースを選んで教師版を要求する。対象コースで `local/tomb:exportteacher` が必要で、標準の教師・編集権限のない教師ロールには既定で付与される。コースへの参加登録がなくても、`moodle/course:view` によりアクセスできるコースは教師版の対象にできる。学生版のコース選択には有効な参加登録を必要とする。

検証モードでは、学生だけでなく教師版を受け取る教師本人も検証対象のコホートへ追加する。教師が対象外の場合は作成ボタンを無効にして理由を表示する。学生版の作成代行は対象学生の利用資格と `local/tomb:delegate` に従うため、教師本人のコホート所属は不要。

実名での教師版には、別途 `local/tomb:exportothersdata` と理由が必要。通常の検証では標準の仮名表示を使用できる。

## 通知・取得・監査

通常の Moodle cron を使う。Tomb 専用の常駐サービスは不要。画面に cron 停滞を表示する。共有サイトで試験のために全 cron を手動で一斉実行しない。

通知は Moodle の通知機構を利用し、既定ではサイト内通知を有効にする。メールは許可のみで、既定有効にはしない。教師代行では、収集完了を本人へ通知し、本人が ZIP 準備を依頼する。教師の進捗画面には学生版の取得リンクを置かない。管理者の取得は実行者 ID と対象版を監査する。

通知済み・ダウンロード開始・本人による「展開して記録を確認しました」は別の記録である。受領 CSV は版単位。本番と検証を混ぜずに絞り込み、未受領の版へ手動リマインドできる。

本人・作成代行・管理一覧は25件ずつ表示する。コース、収集状態、受領状況で絞り込み、管理CSVは同じ条件の全ページを出力する。「収集完了」でもZIP準備中の場合があるため、行内の案内を確認する。未受領は材料削除済みの版を除外する。本人は配送期限後も履歴と停止理由を確認できるが、取得や再生成の可否は現在の資格・モード・期限に従う。

作成時に出力言語を日本語・英語から選ぶ。代行の学生版は本人の言語設定を標準にする。完成した版の言語は固定し、画面の言語を変えても同じ版の再構成結果は変わらない。別の言語で保存したい場合は新しい版を作成する。通知は受信者の言語、教材本文と元ファイルは元の言語を維持する。

## 容量見積もりと実測

`php local/tomb/cli/estimate.php --userid=USER_ID --courses=COURSE_ID` は可視活動と添付のメタデータだけを読み、ZIPや要求を作らない。重複を除いた既知の共有原本サイズと、ページ数等に基づく保存材料・Privacy索引・一時ZIP・完成キャッシュの仮予算を表示する。提出物・フォーラム・受験等の全サイズは収集まで未確定で、`is_upper_bound` は false。生成中の容量ガードとZIP予約は引き続き必要である。

管理一覧の「処理時間・保存量の実測」では、収集・組立の秒数とPHPプロセスのピークメモリ、参照原本・圧縮材料・Privacy索引・ZIPのサイズを確認できる。ピークはプロセス全体の値、共有原本は論理的な参照量であり、利用者ごとの物理コピー量ではない。DB索引やファイルシステムの管理領域を含む実ディスク使用量とも異なる。

監査は SHA-256 による連鎖を検証できる。DB 全体を書き換えられる者への改ざん防止装置ではない。承認済みの個人データ削除では識別情報を消し、連鎖を再計算して、消去前の末尾ハッシュを `privacy_checkpoint` に記録する。従来の外部チェックポイントとの差はこの明示操作として確認する。独立した照合を必要とする場合は、権限付き JSONL 出力を別の保管先に保持する。

## 障害時

| 表示・原因 | 対応 |
|---|---|
| 受付のまま | `cli/status.php` と通常 cron を確認。モード・コーホート・期限も確認 |
| 容量待機 | 容量制限と空きを確認。清掃タスクが待機要求を再受付する |
| 単一ZIPが上限超過 | 設定確認を明示する。無期限に待機しない |
| キャッシュ破損 | 検出したキャッシュを破棄し、本人が同じ版の再準備を要求 |
| 保存材料の欠損 | 該当版を配信停止。本人と管理者へ通知し、別の版として再生成 |
| ワーカー中断 | ロックの非保持と10分以上の古いハートビートを確認して整理。収集は失敗表示、組立は固定材料から再受付 |
| 取得期限切れ | 取得を停止。材料削除は別の明示操作 |

空き容量ガードが収集中に作動した場合、アルファ版はその要求を失敗として知らせる。空きを確保して新しい版を依頼する。部分生成を正常な完成品として渡さない。

## 検証用データ

`cli/fixture.php --create --secrets=/private/tomb-fixture.json` で専用コース、コーホート、学生2名・教師1名を作成できる。JSON は `password` に16文字以上のランダムなパスワードを指定し、CLI 実行者だけが読み書きできる0600のファイルとして事前に用意する。コース・アカウントの識別子は `tomb-alpha-fixture` / `tomb.alpha.*`。同名で識別子の違う利用者は再利用しない。

小テストの検証では、サイトに存在する5形式のテスト問題への参照を専用小テストへ追加し、専用学生の受験を新規作成する。元の問題や既存受験を変更しない。自動生成するアカウントのメールは `example.invalid` で外部交付に使わない。

`tests/integration.php --run` はこの専用コースと検証モードを必須とする。新しい試験版を作り、その版の材料欠損・削除を再現する。小テストのレビュー設定は `finally` で復元する。`tests/named_export.php --run` は専用コース内だけで実名権限を一時付与し、理由と監査を確認後に復元する。`tests/cache_lifecycle.php` は破損させてよい専用学生版のキャッシュだけを指定して実行し、別PHPプロセスのロックで配信中を再現する。サイト全体のテスト DB 初期化は行わない。

`tests/teacher_access.php --run` は編集権限のない教師、登録なしでコース閲覧権限を持つ教師、学生の出力とZIPを確認する。閲覧・出力権限の不足、実名権限、検証コホートの制限も確認する。専用コースの一時変更はトランザクションで戻し、生成した試験用の保存材料を削除する。

0.3の `tests/iteration.php --run` は要求125件と監査300件の合成メタデータでページ境界・権限・状態・監査分割処理を確認し、トランザクションをロールバックする。`tests/language_capacity.php --run` は専用コースで最大5件を順次生成し、日英と権限、容量を確認する。1件64 MiBを試験上限とし、各要求の材料を検証後に削除する。共有サイトの同時実行数は増やさない。

`cli/demo.php --create` は既存の専用アカウントを使ってデモコース `tomb-demo-03` を別途追加する。fixtureコースを上書きしない。コース作成・登録・提出・評価を伴うため、検証専用の環境で明示実行する。無効な例示メール宛の標準課題通知はMoodleが送信を抑止し、警告を出す場合がある。パスワードは作成・変更しない。

本番データを含む生成 ZIP、認証状態、アカウントのパスワードファイルを Git に入れない。配布物作成先 `build/`、検証出力 `test-output/` は Git の対象外。

Privacy APIと旧版移行は [個人データの扱い](PRIVACY.md)を参照。既存の教師用索引を持たない0.1 ZIPを過去の内容として書き換えることはしない。
