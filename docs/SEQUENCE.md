# 操作と処理の流れ

Tombは、Moodleの教材・学習成果を静的HTMLとして保存し、要求に応じてZIPを用意します。収集とZIP組立は通常のMoodle cronで非同期に実行します。利用者は処理中に画面を閉じても構いません。

以下は0.3.0-alphaの動作を表したMermaidのシーケンス図です。[画面例](SCREENSHOTS.md)と併せて確認できます。図1・2は正常に完了する場合を示し、待機・失敗時の扱いは末尾の表にまとめています。

## 1. 利用者が出力を要求し、記録を受け取る

「記録を作成して受け取る」は、収集とZIP準備をまとめて依頼する操作です。本人への通知は、ZIPの組立・検証が完了した後に届きます。

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant W as Tomb Web UI
    participant J as 非同期処理<br/>Moodle cron
    participant M as Moodleの教材<br/>学習成果
    participant S as 固定材料・一時ZIP
    participant N as Moodle通知

    U->>W: ログインし、コースと出力言語を選ぶ
    U->>W: 「記録を作成して受け取る」
    W->>W: 権限・履修・運用モード・期限・容量を確認
    W->>J: 収集ジョブを登録（ZIP準備も依頼）
    W-->>U: 受付・進捗画面を表示
    Note over U,W: 処理中は画面を閉じてもよい

    J->>J: 収集ジョブを開始し、利用資格を再確認
    J->>M: 本人の閲覧権限で教材・提出・評価等を収集
    M-->>J: 閲覧が許可された内容と添付
    J->>S: HTML・元ファイル参照・組立計画を固定
    Note over J,S: 出力言語も版ごとに固定する
    J->>J: ZIP組立ジョブを登録
    J->>S: 容量を予約し、固定材料からZIPを組み立てる
    J->>J: サイズ・CRC等を検証し、ZIPのハッシュを確定
    J->>S: 検証済みZIPを期限付きで保持
    J->>N: ダウンロード準備完了の通知を依頼
    N-->>U: 本人向けの完成通知

    U->>W: 通知から記録を開き、ダウンロード
    W->>W: ログイン・取得権限・期限を再確認
    W->>S: 有効なZIPとハッシュを確認
    S-->>W: 検証済みZIP
    W->>W: 取得開始を記録
    W-->>U: ZIPを配信（Rangeによる部分取得にも対応）
    U->>U: ZIPをすべて展開し、index.htmlを開く
    Note over U: オフラインで教材・提出物・講評・成績を閲覧
    U->>W: 「展開して記録を確認しました」
    W->>W: 本人による受取確認を記録
    W-->>U: 受取確認済みを表示
```

対応する画面：[出力要求](screenshots/0.3/08-learner-request.png)、[完成通知と取得](screenshots/0.3/05-download-and-notification.png)、[オフラインのホーム](screenshots/0.3/01-offline-home-ja.png)。

教師が自分の教師版を作成する場合も、収集から取得までの流れは同じです。収集対象は教師の採点・成績閲覧権限に従い、実名出力には追加権限と理由が必要です。

## 2. 管理者が学生版の作成を代行し、受領状況を確認する

管理者は運用設定を整え、コース単位で学生版を一括受付できます。代行ではまず収集を行い、学生本人がZIP準備を依頼するまで完成ZIPを作りません。

```mermaid
sequenceDiagram
    autonumber
    actor A as 管理者
    participant W as Tomb Web UI
    participant J as 非同期処理<br/>Moodle cron
    participant S as 固定材料・一時ZIP
    participant N as Moodle通知
    actor U as 学生本人

    A->>W: 容量・配送期限・検証対象等を設定
    A->>W: 条件を満たす運用モードに切り替える
    W-->>A: 現在の運用モードを表示
    A->>W: コースと対象学生を選び、一括受付（最大20名）
    W->>W: 実行者の権限と対象学生の利用資格を確認
    loop 受付条件を満たす学生ごと
        W->>J: 本人向け収集ジョブを登録
    end
    W-->>A: 利用者ごとの受付成功・失敗を表示

    loop 受け付けた学生ごと
        J->>J: 学生本人の権限で内容を収集・検証
        J->>S: 学生版の固定材料を保存
        J->>N: 収集完了の通知を依頼
        N-->>U: ログインしてZIP準備を依頼できる旨を通知
    end
    Note over J,S: この段階では完成ZIPを保持しない

    U->>W: ログインし、「ZIPの準備を依頼」
    W->>W: 本人の取得権限・期限を確認
    W->>J: ZIP組立ジョブを登録
    W-->>U: ZIP準備中を表示
    J->>S: 固定材料からZIPを組み立てて検証・保持
    J->>N: ダウンロード準備完了の通知を依頼
    N-->>U: 本人向けの完成通知
    U->>W: ZIPをダウンロード
    W->>W: 権限・期限・ZIPを確認し、取得開始を記録
    W-->>U: ZIPを配信
    opt 本人が内容確認を終えた場合
        U->>U: 展開して保存内容を確認
        U->>W: 本人の受取確認を送信
    end

    A->>W: コース・状態・受領状況で一覧を絞り込む
    W-->>A: 通知済み・取得開始・本人確認の状況を表示
    opt 受領状況を保存する
        A->>W: 表示条件の受領状況をCSVで取得
        W-->>A: 同じ条件の全ページ分を出力
    end
    opt 受取確認がまだない対象へ案内する
        A->>W: 対象版の「本人に再通知」を実行
        W->>N: 再通知を依頼
        N-->>U: 受け取りの案内
    end
```

対応する画面：[運用モード](screenshots/0.3/09-administrator-controls.png)、[一括受付](screenshots/0.3/10-administrator-batch-request.png)、[未受領の管理](screenshots/0.3/07-receipt-management.png)。

教師も、権限のある担当コースで学生版の作成を代行できます。代行権限だけでは学生版を取得できません。Tomb管理権限を持つ管理者の取得は別途認可・監査され、学生本人の受取確認としては扱いません。

## 3. 同じ版を再取得する

完成ZIPは一時キャッシュです。キャッシュの期限が切れても、保存材料と取得資格が残っていれば、同じ版を再準備できます。キャッシュ期限と配送期限は別に判定します。

```mermaid
sequenceDiagram
    autonumber
    actor U as 利用者
    participant W as Tomb Web UI
    participant J as 非同期処理<br/>Moodle cron
    participant S as 固定材料・一時ZIP
    participant N as Moodle通知

    U->>W: 過去の記録を開く
    W->>W: 取得権限・運用モード・配送期限を確認
    alt 取得が許可されていない
        W-->>U: 停止理由を表示（取得不可）
    else 取得が許可されている
        W->>S: 保存材料の状態とZIPキャッシュを確認
        alt 有効なZIPがある
            W-->>U: ダウンロードボタンを表示
            U->>W: ダウンロード
            W->>W: 権限・期限・ZIPハッシュを再確認
            W-->>U: 同じ版のZIPを配信
        else ZIPだけが期限切れ・準備失敗
            W-->>U: 同じ版のZIP再準備を案内
            U->>W: ZIP準備を依頼
            W->>J: 組立ジョブを登録
            J->>S: 保存材料・固定した組立計画を読む
            Note over J,S: 現在の教材を再収集せず、言語も変更しない
            J->>S: 同じバイト列のZIPを再構成して検証・保持
            J->>N: ダウンロード準備完了の通知を依頼
            N-->>U: 再取得できる旨を通知
        else 保存材料が欠損、または削除済み
            W-->>U: その版の取得を停止
            Note over U,W: 材料欠損は新しい版で対応<br/>Privacy削除済みの版は復活させない
        end
    end
```

材料欠損が組立中に見つかった場合も、その版の配信を停止します。新しい版の作成は現在の利用資格・受付条件に従い、同じ版の再準備とは別の操作になります。

## 状態と通知の読み方

| 状態・記録 | 意味と次の操作 |
|---|---|
| 収集完了 | 静的ページと保存材料が確定した状態。ZIPが取得可能とは限らない。代行の場合は本人がZIP準備を依頼する |
| 容量待機 | ZIPの保存容量を確保できない状態。通常cronの清掃処理が待機中の組立を再受付する |
| 単一ZIPの上限超過 | 管理者による容量設定等の確認が必要。空き待ちだけでは解消しない |
| ZIP準備失敗 | 材料が残っていれば同じ版を再準備する。収集からのやり直しは不要 |
| 保存材料の欠損 | その版を配信停止にする。新しい版は現在の内容から生成する |
| Privacy削除・材料削除 | 削除された版は再取得できない。[個人データと移行](PRIVACY.md)を参照 |
| 配送期限終了 | 認証済みでも取得を停止する。材料の削除は別の明示操作 |
| 通知済み | 完成通知の送信を記録した状態。本人が読んだことや取得完了を示さない |
| 取得開始 | ZIP配信の開始を記録した状態。最後まで保存・展開できたことを示さない |
| 本人確認済み | 学生本人が展開・内容確認後に受取確認を送信した状態 |

通知はMoodleの通知機構を使います。既定ではサイト内通知が有効で、メール通知は設定に従います。詳細な設定と障害時の対応は [運用手順](OPERATIONS.md)を参照してください。
