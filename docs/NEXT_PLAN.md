# 次の実装計画：0.3.0-alpha

作成日：2026-09-20。対象の基準は0.2.0-alpha、コミット `06aff50`。本書は「plan next」への計画成果物であり、以下の実装・検証は未着手。既存のユーザー決定と、共有Moodleを稼働させ続ける条件を引き継ぐ。

次の到達点は、対象者と記録が増えても管理者が未受領・失敗を追跡でき、学生が次の操作を判断できるアルファ版とする。WBSで残っている日英表示を整え、実際の取得からオフライン閲覧までを提出用に撮影する。

## 現状から選んだ優先事項

- 学生の履歴と作成代行の履歴は直近50件、管理一覧は直近100件の固定表示。古い対象へ辿るページ送りがない。
- `cli/estimate.php` は閲覧可能な活動数を列挙する。保存材料・一時ZIPを合わせた容量の見通しは出していない。
- Privacy削除時の監査処理は全行をメモリに読み込む。教師版も複数人分の本文を一つのページにまとめるため、件数増加時のメモリを測定する必要がある。これらはコード上の調査対象であり、実負荷障害が確認されたという意味ではない。
- Moodle画面と静的HTMLには日本語の直接記述が残る。既存WBS A-03の日英表示を完了させる。
- 現在のスクリーンショットには検証用の文字列がある。検証データを保持し、提出用には専用の自然な文章のデータを追加する。

## 実装判断

### C-01 / C-02：取得までの操作

一覧の条件とCSVの条件を共通化し、件数と表示範囲を明示する。通知済み・取得開始・本人確認済みは引き続き別々に扱う。教師が代行した学生版は進捗だけを扱い、取得リンクを教師へ渡さない。

再試行は利用者による明示操作を基本とする。容量待機の既存の再受付は維持する。ZIP準備だけの失敗は同じ固定材料から再準備し、保存材料を失った版は配信停止のまま新しい版の要求を案内する。内容を自動再生成したり、Privacyで廃棄した材料を復活させたりしない。

実装時に、学生画面の状態説明とボタンを対にして確認する。内部例外の全文は管理用記録に残し、学生には原因の分類と次の操作を表示する。

### C-03：共有環境での計測範囲

まずローカルの合成データで多数の目録・監査行を確認する。共有Moodleでは専用対象だけを用い、1件→最大5件の順次処理から始める。同時生成・組立・配信の既定値は増やさない。初期上限は1件64 MiB程度、追加キャッシュ合計256 MiB以内とし、見積もり超過は実行前に中止する。

各段階の前後に通常ログイン・コース表示・cron・空き容量を確認し、異常や他のアップグレードがあればTombの次の試験を止める。容量待機や上限超過はTombの小さな試験設定で再現し、共有ディスクを圧迫して再現しない。既存の専用デモや他プラグインのデータを消さず、新規試験分だけを識別して後片付けする。

20件以上のジョブ、大量の教師版、長時間の帯域制御は、分離した環境を準備できた場合の追加検証とする。共有環境の5件の結果から、数千人への配送性能を保証しない。処理時間の目標値は最初の実測後に設定する。

容量の見積もりは生成を開始するための保守的な確認とし、生成中の容量監視・ZIP組立の予約も維持する。活動数だけから正確なバイト数を算出したようには表示しない。

### C-04：言語と固定した記録

学生の言語を標準にして作成時の出力言語を固定する。必要なDB変更があればTombだけの更新手順を用意する。既存版のキャッシュ再構成で現在の言語設定を使って本文を翻訳し直さない。言語を変えた出力は新しい版として扱い、0.1・0.2の完成版は保持する。

日時・数値・長い英語ラベル、キーボード操作、スマートフォン幅、JavaScript無効での本文閲覧を併せて確認する。教材本文の翻訳は対象にしない。

### C-05：提出用の見せ方

検証マーカーを含む既存コースと生成済みZIPは証拠として保持する。新しい専用コースに、実在者を含まない教材・提出物・講評を用意する。旧画面の加工で機能を表現せず、動く版を通常操作して撮影する。

主要画面は5〜7枚に絞り、長い全ページ画像とは別に読みやすい表示幅で撮影する。ホーム、課題と講評、小テスト、完成通知・受け取り、教師版、未受領管理を候補とする。提出先の枚数・言語指定が後から判明した場合は構成を調整する。

## 0.3の完了判定と残件

権限漏れ、保存内容の欠落・内部リンク切れ、同一版の変化、共有サイトの稼働阻害が残る場合は0.3を完成扱いにしない。件数表示・CSV・言語追加は、作成代行と本人取得の境界を含めて検証する。既存の115項目を単に繰り返すだけでなく、今回変更する境界に対応する確認を加える。

次の項目は後続計画に残す。

- Windows / Safari実機確認。利用可能な環境を調べ、確保できなければ未検証として記録する。Linux上の別エンジン試験で実機確認を代替したとは扱わない。
- 本番規模の負荷試験と長時間ダウンロード。
- 自動リマインド、サイト横断の大量一括受付、詳細ルーブリック、新しい活動形式への対応。
- 停止済み利用者への機関交付。本人確認・交付先の運用が必要なため、管理者ダウンロードを交付完了とみなさない。
- GitHub送信。送信先リポジトリ・公開範囲が未指定。指定済みの作者でローカルコミットを継続する。

旧版Privacy移行のために、比較用デモを自動削除しない。必要な明示移行は[Privacy設計](PRIVACY.md)を引き継ぐ。
